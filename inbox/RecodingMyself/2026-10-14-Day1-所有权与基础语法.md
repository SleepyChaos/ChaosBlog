Day 1 小记：基本语法 + 所有权机制。所有权比想象中简单，核心就是几条规则，有点像规则怪谈——遵守它，编译器就放你过。

## 一、所有权：四条规则

1. **每个值都有一个所有者**，通常就是持有它的变量。所有者离开作用域（一般是 `{}`）时，值被释放（drop）。
2. **所有权失效的变量不可再使用**——值一旦被移走，旧变量就成了空壳。
3. **赋值会转移所有权**：`let x = y` 之后，`y` 不可用。

> [!warning] 校正：规则 3 只对**未实现 `Copy` 的类型**成立。`i32` 这类 Copy 类型赋值时是复制，不是转移，原变量仍可用。
>
> ```rust
> let s1 = String::from("hello");
> let s2 = s1; // 移动：s1 失效
>
> let x = 5;
> let y = x; // 复制：x 仍可用
> println!("{x} {y}");
> ```

4. **借用 `&`**：临时出借访问权，所有权不转移。`&` 创建的就是引用，借用和引用是同一个东西。

```rust
fn length(s: &String) -> usize {
    s.len()
}

let s1 = String::from("hello");
let n = length(&s1); // 借用，s1 依然可用
```

## 二、不可变与可变

1. Rust 变量**默认不可变**。
2. 可变变量需要标记 `mut`：`let mut x = 5;`
3. 借用 + 可变 = **可变借用** `&mut`。
4. **借用规则**：同一时刻，要么多个**不可变**借用，要么一个可变借用，二者的作用域不可重叠。

> [!warning] 校正：规则 4 的"多个借用"应为"多个**不可变**借用"。不可变借用和可变借用不能共存。
>
> ```rust
> let mut s = String::from("hello");
> let r1 = &s; // 不可变借用
> let r2 = &s; // 再来一个不可变借用，没问题
> let r3 = &mut s; // ❌ 编译错误：不可变借用还活着，不能出借可变借用
> println!("{r1}");
> ```

## 三、函数参数：意图写在签名里

这些规范导致函数参数的写法必须严谨：可能被改变的传入参数带 `mut`，不可变的用 `&`。这是一种**显式声明**——函数签名本身就是契约，调用者一眼能看出这个函数会不会动我的数据。

> [!warning] 校正：`mut` 有两个位置，含义不同——
>
> - `mut x: T`：绑定本身可变（函数内部可以给 `x` 重新赋值）；
> - `x: &mut T`：传入的是可变引用（函数可以通过它修改调用者的数据）。
>
> 前者只影响函数内部，后者影响调用者。

```rust
fn push_item(items: &mut Vec<String>, item: String) {
    items.push(item); // 通过可变引用修改调用者的数据
}
```

## 四、基础语法拾遗

### `for x in xs`

```rust
let xs = vec![1, 2, 3];
for x in xs {
    println!("{x}");
}
```

> [!tip] `for x in xs` 会**移动** `xs`（`Vec` 不是 Copy 类型），循环之后 `xs` 不可用。只想读不想拿走，用 `for x in &xs`。

### 函数返回值是最后一行

函数体最后一行、不带分号的表达式就是返回值（尾表达式）。加了分号就变成语句，返回 `()`。

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // 尾表达式，即返回值
}
```

### `Ok(...)` 不是通用返回值

> [!warning] 校正：`Ok(...)` 不是"返回值可以用 ok() 代替"，它是 `Result` 枚举的**成功变体**，只有当函数签名返回 `Result<T, E>` 时才用；而且首字母大写，是 `Ok` 不是 `ok`。
>
> ```rust
> fn read_tasks() -> Result<Vec<String>, std::io::Error> {
>     // ...
>     Ok(tasks) // 把 tasks 包装进 Result 的成功分支
> }
> ```

### `::` 与 `.`：关联函数 vs 方法

- `::`：**关联函数**，不带 `self`，通过类型名调用，如 `String::from("hi")`；
- `.`：**方法**，带 `self` / `&self` / `&mut self`，通过值调用，如 `s.len()`。

> [!warning] 校正：Rust 没有"类"，准确的说法是"类型"。`::` 是路径语法，`.` 是方法调用语法。

### `match`：模式匹配，不只是 switch

`match` 像 switch，但更强：匹配的是**模式**，而且必须**穷尽**所有可能。`Some("x")` 是 `Option` 的变体。

```rust
let x = Some("x");
match x {
    Some(v) => println!("有值：{v}"),
    None => println!("没有值"),
}
```

### 类型标注：`let x: String`

类型写在变量名后面，和 Go 一样：

```rust
let x: String = String::from("hi");
```

### `?`：错误向上传递

> [!warning] 校正：`?` 不是"放在函数后"，而是跟在**返回 `Result` / `Option` 的表达式**后面（通常是函数调用）。它做的是：成功则解包，失败则提前返回错误。且要求外层函数也返回相容的 `Result` / `Option`。
>
> ```rust
> fn load() -> Result<Vec<String>, std::io::Error> {
>     let tasks = read_tasks()?; // 出错直接返回 Err，成功解包成 Vec<String>
>     Ok(tasks)
> }
> ```

### `!`：宏调用标记

`println!(...)` 里的 `!` 表示这是一个**宏调用**，编译器在编译时展开宏。

> [!warning] 校正：宏不只是"语法糖"。语法糖是等价的简写，而宏能在编译时生成代码、操作语法树，能力比语法糖大得多。另外 `!` 在别的语境还有别的含义，比如 never 类型 `!`。

```rust
println!("hello"); // println! 是宏，编译时展开
```

## 小结

- 所有权 = 一套"谁拿着、谁能动"的规则，遵守了就不会有悬垂指针和 double free。
- 借用 + 可变性 = 在不转移所有权的前提下，精确控制"能不能改"。
- 待确认：`?` 的 `From` 转换细节、宏的定义方式留给后面。
