## 一、包、模块和 Crate 管理机制（第 7 章）

ps：这个部分涉及到 crate 感觉太底层了，没太学明白。

首先是包（package），emmmm。Rust 里 package 就是 Cargo.toml 描述的那个项目。

> 3.14 注：这里要纠一下。"package 也就是项目的依赖项目"说得不太对。package 是 Cargo.toml 描述的项目本身，不是"依赖项目"；依赖是别的 package。官方的说法是：
>
> "A package is a bundle of one or more crates that provides a set of functionality. A package contains a Cargo.toml file that describes how to build those crates."（《The Rust Programming Language》第 7.1 节）
>
> crate 才是编译器一次处理的最小编译单位："A crate is the smallest amount of code that the Rust compiler considers at a time."

我之前在 Python 里认识的包是文件夹 + `__init__.py` 组成的命名空间，当然这个差异我认为大概只是因为翻译和概念的重叠。

继续，Rust 中和这个类似的是 mod 系统。

### 什么是 mod 和模块树

首先要明确一个东西叫做命名空间，然后模块树就有点像文件路径：程序通过这个树来找到你要使用的文件，而模块 mod 下容纳了哪些文件中你要调用的对象。就像树中的根节点一样，如果一个命名空间下还要加入别的 mod，Rust 需要你先创建一个同名的文件夹和 rs。

such：

```text
src/
├── main.rs
├── todo.rs
├── focus.rs
├── commands.rs
└── commands/
    ├── add.rs
    └── complete.rs
```

```rust
mod todo;
mod focus;
mod commands;
```

调用的时候从 crate 根往下走：

```rust
crate::commands::add
crate::commands::complete
```

> 官方的说法（第 7.2 节）："Modules let us organize code within a crate for readability and easy reuse. Modules also allow us to control the privacy of items, because code within a module is private by default."
>
> 上面这个拆法就是 2018 版的规则：`commands.rs` 是文件模块，它的子模块放在同名的 `commands/` 目录里；`main.rs` 里写一句 `mod commands;` 就行，编译器自己去找 `src/commands.rs`。

## 二、错误处理（第 9 章）

（之前是不是已经涉及到了？和 Result 一起。）

现在来详细点描述。`Result` 是 `Result<T, E>`，代表可能返回两种类型的尝试：E 就是 error，也就是错误类型；T 就是正常返回的变量，比如说 `Ok(1145)`。这也是为什么 Rust 有的时候要返回 `Ok(T)`——当函数要求返回 Result 的时候，一定要返回一些东西，即使是空的 Ok 也行。

> 官方定义（第 9.2 节）：
>
> ```rust
> enum Result<T, E> {
>     Ok(T),
>     Err(E),
> }
> ```
>
> "The Result enum is defined as having two variants, Ok and Err, as follows."
>
> 空的那个 Ok 写作 `Ok(())`，对应 `Result<(), E>`——没有数据也要有个成功的壳。
>
> 3.14 注："T 就是 Some<T> 中的 T"这个说法不对。`Some` 是 `Option` 的变体，`Result` 和 `Option` 是两套不同的枚举；`Result<T, E>` 里的 T 只是"成功时 Ok 里装的值的类型"，跟 `Some` 没关系。

### 错误信息的处理和 ErrorKind

Error 是一种可选的枚举，你可以选择一个具体的错误类型。Error 还能增加具体的注释（因为单纯的 error 是没有报错信息的）。

> 3.14 注：这里两个东西要分开。`io::Error` 是错误值本身，`ErrorKind` 才是它的"类别"枚举（`NotFound`、`InvalidData`……），用 `error.kind()` 取出来再 `match`。官方的例子（第 9.2 节）：
>
> ```rust
> use std::fs::File;
> use std::io::ErrorKind;
>
> fn main() {
>     let greeting_file_result = File::open("hello.txt");
>
>     let greeting_file = match greeting_file_result {
>         Ok(file) => file,
>         Err(error) => match error.kind() {
>             ErrorKind::NotFound => match File::create("hello.txt") {
>                 Ok(fc) => fc,
>                 Err(e) => panic!("Problem creating the file: {e:?}"),
>             },
>             other_error => {
>                 panic!("Problem opening the file: {other_error:?}");
>             }
>         },
>     };
> }
> ```
>
> "增加注释"对应的是 `io::Error::new(kind, "具体文字")`——把类别和一段文字拼成一个错误值。

### panic!（恐慌）

`panic!` 会直接中断程序进程，报错退出；Result 更像是 try，不会强制中断程序，让调用方自己决定怎么办。

> 官方的说法（第 9.1 节）："By default, when a panic occurs, the program starts unwinding, which means Rust walks back up the stack and cleans up the data from each function it encounters."

## 三、序列化（项目补充）

```rust
#[derive(Serialize, Deserialize)]
```

让结构体和枚举可以在 Rust 变量和 JSON 之间进行转化，实现序列化和反序列化，用于更方便地传递信息。

- `serde_json::to_string_pretty()`：把 TodoList 变成可读的 JSON 字符串。
- `serde_json::from_str()`：把 JSON 字符串恢复成 TodoList。
- `fs::write()`：文件不存在时创建，存在时覆盖。
- `fs::read_to_string()`：读取 UTF-8 文本文件。

```rust
let json = serde_json::to_string_pretty(&list)?;
let list: TodoList = serde_json::from_str(&json)?;
```
