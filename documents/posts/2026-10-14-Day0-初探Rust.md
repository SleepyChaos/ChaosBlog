对应 [rust-learning](https://github.com/SleepyChaos/rust-learning) 三周计划的阶段 0（第 1 天）。下一篇是 [Day 1：所有权与基础语法](/ChaosBlog/posts/Day1-所有权与基础语法/)。

## 一、下载 Rust：用 rustup 装

Rust 不直接装编译器，而是装 **rustup**——工具链管理器，由它来安装和管理 `rustc`、`cargo` 等组件，以及切换工具链版本。

```sh
# macOS / Linux（官方安装脚本）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

装完验证：

```sh
rustc --version  # 编译器
cargo --version  # 包管理 + 构建工具
```

> [!tip] 三个东西别混了
>
> - `rustup`：工具链管理器（装什么版本、更新、切换都找它）；
> - `rustc`：编译器（把 `.rs` 编译成可执行文件）；
> - `cargo`：包管理 + 构建工具（建项目、拉依赖、编译、运行、测试）。

日常更新工具链：`rustup update`。官方中文安装说明：<https://rust-lang.org/zh-CN/tools/install/>

## 二、Cargo：基本用法

### 四个基本操作

```sh
cargo new todocli   # 新建项目（生成 Cargo.toml、src/main.rs）
cargo build         # 编译，产物在 target/debug/
cargo run           # 编译 + 运行
cargo test          # 运行测试（单元测试、集成测试、文档测试）
```

实际开发常用组合（也是 `todocli` README 里写的工作流）：

```sh
cargo check   # 只做类型检查，不生成可执行文件，比 build 快
cargo fmt     # 格式化代码
cargo clippy  # 静态检查，给出更严格的代码建议
cargo test    # 跑测试
```

> [!warning] 注意：`cargo check` 不产生可执行文件，它只是"检查能不能编过"。写新功能时先 `check`，阶段结束再 `fmt + clippy + test`。

### 给程序传参数：`--` 的作用

```sh
cargo run -- add 学习所有权和借用
```

`--` 前面的是 cargo 自己的参数，`--` 后面的是**传给程序**的参数。`todocli` 的 `main.rs` 用 `env::args().skip(1)` 拿到这些参数（`skip(1)` 是跳过程序名本身）。

### `Cargo.toml` vs `Cargo.lock`

这是最容易混的一对：

| 文件 | 谁写的 | 内容 | 该不该提交 |
| --- | --- | --- | --- |
| `Cargo.toml` | 你 | 项目清单：包名、版本、edition、依赖的**版本要求**（如 `serde = "1.0"` 表示兼容的 1.x） | 提交，必备 |
| `Cargo.lock` | cargo 生成 | **精确版本快照**：所有依赖（含传递依赖）实际解析到的确切版本 | 二进制项目提交；库项目一般不提交 |

> [!warning] 校正：`Cargo.lock` 是 cargo 自动生成的，**不要手改**。它的意义是"这次构建用的就是这些精确版本"，保证换台机器、隔半年再构建，依赖版本依然一致。`Cargo.toml` 写的是"要求"，`Cargo.lock` 记录的是"实际结果"。

`todocli` 当前的 `Cargo.toml`：

```toml
[package]
name = "todocli"
version = "0.1.0"
edition = "2024"   # Rust 版本（edition），不是 rustc 的版本号

[dependencies]     # 目前为空，不依赖任何第三方库
```

## 三、程序入口与脚手架流程

`todocli` 现在的脚手架只有添加、查看 todo 和帮助功能。`src/main.rs` 的基本路径：

```
输入（命令行参数）
  → 处理（match 分发：add / list / help）
    → 保存 / 读取（tasks.txt）
      → 输出（println!）
```

```rust
fn main() {
    if let Err(error) = run() {
        eprintln!("错误：{error}"); // 错误走标准错误
        std::process::exit(1);    // 非零退出码表示失败
    }
}

fn run() -> io::Result<()> {
    let args: Vec<String> = env::args().skip(1).collect();

    match args.first().map(String::as_str) {
        Some("add") => { /* 校验标题 → 追加写 tasks.txt */ }
        Some("list") => { /* 读 tasks.txt → 编号打印 */ }
        Some("help") | None => print_help(),
        Some(_) => { /* 未知命令：打印帮助并返回错误 */ }
    }

    Ok(())
}
```

几个值得注意的点：

- **程序入口是 `fn main()`**，它调用 `run()`，`run()` 返回 `Result`，出错时 `main` 打印错误并以退出码 1 退出。
- **`?` 在这里已经出现**：`add_task(title.trim())?`、`read_tasks()?`——出错就提前返回 `Err`，把错误向上传递（Day 1 笔记里 `?` 的详细说明见 [Day 1](/ChaosBlog/posts/Day1-所有权与基础语法/)）。
- **标准输出 vs 错误输出**：正常结果用 `println!` 走标准输出（stdout），错误用 `eprintln!` 走标准错误（stderr）。这样重定向输出时，错误信息不会混进正常结果里。
- **数据保存**：任务存在当前目录的 `tasks.txt`，每行一条；文件不存在时 `list` 当作空列表处理，不报错。

## 小结

- 装 Rust = 装 rustup，由它管理 `rustc` 和 `cargo`。
- `Cargo.toml` 是你写的"要求"，`Cargo.lock` 是 cargo 生成的"实际结果"。
- `cargo run -- <参数>`：`--` 后面的才传给程序。
- `todocli` 脚手架流程：参数 → `match` 分发 → 读写 `tasks.txt` → 输出；错误走 `eprintln!` + 退出码 1。
