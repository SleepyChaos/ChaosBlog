每门语言都要回答一个问题:这块内存什么时候释放。C 的答案是手动 `malloc`/`free`,Java 的答案是 GC,而 Rust 的答案是**所有权系统**——在编译期就把事情定了,运行时零开销。这篇记录我对所有权机制的第一次系统理解。

## 三条基本规则

1. 每个值都有一个唯一的所有者(owner),通常就是持有它的变量;
2. 同一时刻,一个值只能有一个所有者;
3. 所有者离开作用域时,值被丢弃(drop),内存随即释放。

```rust
{
    let s = String::from("hello"); // s 是 "hello" 的所有者
    println!("{s}");
} // s 离开作用域,drop 自动调用,内存在这里释放
```

## move:赋值默认是移动,不是复制

这是和直觉冲突最大的地方。把一个 `String` 赋给另一个变量,所有权会**转移**:

```rust
let s1 = String::from("hello");
let s2 = s1;             // 所有权从 s1 移动到 s2
// println!("{s1}");     // 编译错误!s1 已经不再持有这个值
println!("{s2}");        // 正常
```

为什么这样设计?`String` 的数据存在堆上,栈上只有指针、长度和容量。如果赋值是浅拷贝,`s1` 和 `s2` 会指向同一块堆内存,离开作用域时就会 drop 两次。C 里这类 double free 是运行期炸弹,Rust 直接让它过不了编译。

> [!warning] 高频报错
> `error[E0382]: borrow of moved value` 几乎是每个 Rust 新手见到的第一个错误。看到它就意味着:值的所有权已经移走了,别再用旧变量,或者改用下面的借用。

## borrow:只借不拿,用引用访问

不想转移所有权、只是想读一下或改一下,用引用 `&`:

```rust
fn length(s: &String) -> usize {  // 借用,函数结束后什么也不发生
    s.len()
}

let s1 = String::from("hello");
let n = length(&s1);
println!("{s1} 长度 {n}");  // s1 依然可用
```

规则同样严格:**同一时刻,要么有任意多个不可变引用 `&T`,要么只有一个可变引用 `&mut T`,两者不能共存**。这是编译器在编译期防数据竞争的代价,也是 Rust 代码写起来"别扭"的主要来源。

## clone:需要深拷贝时,明确付出代价

真的要两份独立数据,就显式调用 `clone()`,把堆拷贝的成本写在明面上:

```rust
let s1 = String::from("hello");
let s2 = s1.clone();    // 深拷贝,s1 和 s2 各自独立
println!("{s1} {s2}");  // 都能用
```

注意 `i32` 这类实现了 `Copy` trait 的简单类型赋值时是按位复制,不发生 move,所以 `let x2 = x1;` 之后 `x1` 依然可用——这和 `String` 的行为不同,本质区别在数据在栈上还是堆上。

> [!tip] 学习心得
> 与其把 E0382 当报错,不如把它当编译器在帮你标出"这块内存的生命周期图"。理解了 move 是默认行为之后,后面学生命周期、`Rc`、智能指针都是在回答同一个问题的延伸:当单一所有者不够用时怎么办。

## 小结

| 行为 | 语法 | 堆数据 | 原变量 |
| --- | --- | --- | --- |
| 移动(默认) | `let s2 = s1;` | 不拷贝 | 失效 |
| 借用 | `let r = &s1;` | 不拷贝 | 可用 |
| 深拷贝 | `let s2 = s1.clone();` | 拷贝 | 可用 |
| 按位复制 | `let x2 = x1;`(Copy 类型) | 无堆数据 | 可用 |
